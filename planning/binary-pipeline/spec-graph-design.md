# 自定义规格与多pass：后续实施设计草案

本文件是Overnight D的PLAN_ONLY成果草案，记录下一主线的具体方案；没有这些功能的代码授权，也不描述为当前能力。最终文件归属和前置能力须用B/C实际交付核实。总体目标由delta.md拥有，B/C各自设计与实际验收拥有其当前状态。

## 从“两个实现相等”到“实现满足固定目标”

任务发起者固定输入/输出ABI、合法输入范围以及Lean性质`P : Input → Prop`和`R : Input → Output → Prop`。Input包含长度、外部资源容量与外部初始数据；Output包含固定外部边界内的最终资源。候选只能更换HLSL、私有scratch、pass图和证明，不能同时更换任务的P/R或观察函数。验证两份实现时，两边分别满足同一个固定规格，再证明需要的输出关系。

规格模块只依赖固定ABI、数学库与已绑定的规格辅助定义，不导入候选生成模型、候选算法或提交证明。任务清单指向准确模块/定义及依赖；检查器先冻结它们，再转换候选并生成完整目标。P允许依赖输入数组，R允许逐元素、全数组、最大/加权误差及依赖输入的分支预算，不压缩成若干预设JSON误差模式。

Domain只包含公开的类型、长度、资源声明和语义profile范围。完整目标要求满足Domain和固定P的每个输入都能正常完成，所有安全与frame义务成立，正常结果满足R。安全义务包含越界、局部/临时内存未初始化、冲突及缺同步检查，不能只证明输出关系。首批解释器确定性，可通过明确的正常/故障结果定义目标；不能仅写“如果存在一个输出则R”，让故障或无输出空洞通过。

P由任务发起者负责制定，其输入限制也界定安全结论的适用范围。工具保证候选不能替换既定P/R或从候选模型导入它们，不承诺一般性判定P是否合理、非空或间接编码了安全条件。任务制定时应给出真实输入约定，不用候选自己的安全定义作为前提；这属于规格信任边界，不是本项目额外开发一个任意Lean性质审计器的承诺。

未来存在多个允许执行时，要有正常执行存在性并约束全部允许执行，不能选择一条好调度。工具超时/环境错误是检查结果，不是算法的数学输出，不能混入程序Outcome后当作正确终止。

P由任务发起者固定，逻辑上可为空域；不额外强制所有自定义规格必须带非空见证。首批验收任务提供具体合法输入见证，并覆盖误差条件的各分支，用以识别测试空洞。规格替换属于另一任务，不算候选完成原任务。

## 单pass先跑通规格接口

先复用C的纯uint单pass实现、内存和安全目标，让一个候选满足固定P/R；不为规格另写HLSL解释器。安全、正常完成、输出R和外部frame在同一目标中绑定，提交证明不能重定义expected。CLI/runner沿用现有本地工具、workspace锁和公理审计，新增任务描述及规格加载职责。

用两个不同任务检验接口而不是先造复杂配置语言。第一任务要求uint数组逐元素输出为数学上的2*floor(input/2)。第二任务以输入恒等值为目标并允许非零误差：实际候选用`x - (x & 1u)`取不大于x的偶数；令E为整个输出与输入的绝对差之和，S为输入总和，N为有效长度。固定R要求S<2N时E≤N，否则2E≤S。两分支均提供可达见证；错误版减去低两位，在例如全3输入时超过预算。这验证输入依赖与整体误差接口，不冒称浮点采样/BRDF误差已经完成。

固定本地库已有Nat.and_one_is_mod及Finset.sum_nat_mod，UInt32运算也已有精确位向量/自然数连接；可以据此证明单元素误差至多1，再组合全数组预算。上述是实际定义可用性的只读核实，尚未为这两个未来任务运行Lean或实现规格入口。

## 图是明确的调度输入

图是有限数据描述，不执行任意Python/C++回调，不分析Unity或真实宿主代码。它声明外部资源和私有scratch、每pass的HLSL/入口/资源寄存器映射、uniform绑定、dispatch尺寸、执行依赖、资源发布以及最终观察边界。最终报告说明结论基于所提交图，不声称已经验证真实Direct3D宿主的屏障调用。

首图只需要N、固定块大小32、块数ceil(N/32)和相应dispatch组数。用受限的长度引用与固定倍数/向上取整尺寸形式，先不建立通用表达式DSL。尺寸在Nat计算，转换uint uniform和dispatch ID前逐项证明可表示及不溢出；HLSL内部地址仍使用uint32运算，二者不能暗中替换。

首例资源物理identity独立且布局固定，输入只读、输出可写，scratch由各候选图私有；别名或不同view布局先明确拒绝，不引入offset/stride/格式换算。可用合法N上界取C实际已验收契约、尺寸和dispatch限制的交集，公开表达为1≤N≤Nmax，不在C交付以前臆定数值。

图的外部ABI与规格保持固定，候选可以改scratch数量、pass划分和连接方式。只观察外部最终资源并检查未声明修改资源/输出尾部保持，不能要求不同scratch也相等。

## 内存组合所缺的真实能力

B只提供最多64次的静态展开，C只提供单pass scalar uint访问、任意初始内存及无跨线程冲突；二者不自动等于可做多pass scan。后续需补三个明确层次：

1. 让B的静态循环与C资源事件组合，循环中每次访问保留其guard、地址、当时overlay和安全义务。
2. 支持规范符号有限循环，把实际HLSL的counter/bound/state解释为精确Lean有限fold。证明counter递增不回绕且bound合法；不展开某个样本长度，不用fuel截断，也不另写Lean候选算法代替实际源码。
3. 加入scratch初始化与跨pass发布：外部可读内存初始有值，scratch初始不可读；Store初始化地址，Load必须证明当时已初始化。producer正常完成且图中发布相关资源后，consumer才可见这些写入。pass在文件里排在后面不自动补发布。

首例没有pass内线程通信，可继续使用C的unique-writer内存语义：每pass先证bounds/初始化/无冲突，再把安全最终内存接给后继。图为有限无环结构，完整目标包括各pass完成及frame。缺发布的图能够导入，但真实可见性安全命题失败；不能用缺字段或导入器不支持充数。

C的首合同还使用固定容量与固定launch，不能把其若干固定Count运行拼成符号N图。图发射层需从图的Nat尺寸定义向每pass传入符号capacity/线程数，并复用同一真实HLSL kernel；生成的safe在这些实际参数下量化全部合法N。容量、launch与uniform的表示边界属于图的固定合同，不能把实际uint地址算术改成无界Nat。这个参数化接点与符号循环、发布层一起具体化，不冒称C已提供。

发布模型是需要独立P和下一批批准的新图合同，不假称现有两线程VerCors组内barrier原型提供了它。首例不必扩展组内同步。将来采用外部安全后端时，应消费相同lowered访问行为并明确guard/地址/循环/发布映射；只把两个报告绑定到同一HLSL哈希不能证明模型对应。

### 首图的顺序与发布候选模型

首例选择按文件数组顺序执行的有限pass链，作为有限DAG的特例。依赖字段核对节点存在、无环且producer位于consumer之前；结论基于这一个明确schedule，不额外承诺其它拓扑顺序正确。依赖、执行结束与资源发布是三个不同约定，先执行不自动发布。

图状态包含提交内存C、已发布可读快照V、已初始化位置I、已发布且初始化位置J，以及存在未发布更新的位置D。位置是物理identity与地址的组合。外部合法输入区域初始I/J成立且C=V=initial；scratch初始I/J不成立，D为空。底层总内存函数仍可有任意值，读取安全不能把它当作初始化。

每个pass的各线程从同一V执行，继续使用C的线程内overlay与有序accesses。令K(t)=kernel(V,count,t)，W为该pass实际enabled Store触及的位置；结束后使用`C'=finish(threads,C,K)`合并，只在W更新I和D。kernel的输入是V，而finish的保留基底是C：读不到未发布的新C，未写位置也不会被旧V覆盖。初始化更新为I'=I∪W，未发布集合更新为D'=D∪W。

每条enabled Load除bounds及WW/WR外，须满足：本线程访问前缀中已有enabled Store写入同址，或者J在该址成立且该址不在D。前缀顺序和Store实际guard必须保留，最终touched集合不能代替它。只检查J会错误允许读取已经初始化、但最近被修改而尚未发布的外部地址。

整资源publish把所列identity上的当前C复制到V、I复制到J并清除相应D，其它资源保持。不用额外整数版本号也能表达首例需要的新鲜性。最终观察区域须已初始化且没有dirty位置；外部Frame检查实际提交内存C，避免未发布的破坏被V隐藏。外部ABI由任务固定，候选不能把外部资源改标为scratch；私有scratch不参与外部结果等价。

图任务的固定规格身份应只绑定外部ABI、合法输入域、P/R及执行合同；候选私有scratch、pass划分和具体launch属于被验证的图，不放入两图必须共享的任务身份。单pass首规格片固定整个Compute约束的方案，不能未经扩展直接充当可变多pass图的任务格式。

真实负控包括：producer完整写入但漏publish后consumer读取；publish存在却遗漏尾块写入；外部已初始化位置被改写但未发布后再次读取。三者均应导入并在对应初始化/新鲜性安全命题失败。另有状态合并回归：A写X不发布、B仅写Y、随后发布X，A对X的写入必须仍在，检验finish是否误用V作保留基底。

该候选模型由只读规划调查具体化，尚未独立P或实现；实际kernel/Access/ThreadResult类型和符号循环访问序列须在C交付后对齐。它选择了第一例的明确约定，不声称覆盖全部GPU弱内存或真实宿主屏障。

## 两图uint32前缀和的实际方案

固定块大小32。共同首pass对每个i<N，计算b=i>>5、lane=i&31、base=(i>>5)<<5，进行32次固定循环，仅当k≤lane时累加Input[base+k]。写Local[i]，由lane==31或i==N−1的唯一线程写BlockSums[b]。线程i≥N在入口退出，因此尾块也有唯一有效块和写者，不读取本pass其他线程的中间结果。

三pass图：块内前缀并发布Local/BlockSums；每个b<ceil(N/32)符号循环累加BlockSums[0..b]，写并发布ScannedSums；最后写Output[i]=Local[i]+(b==0?0:ScannedSums[b−1])。

两pass图：同一首pass并发布Local/BlockSums；每个i<N符号循环累加BlockSums[0..b−1]，加Local[i]写Output。允许更慢的首个实现，目标是先验证不同pass组织，不宣称高性能scan。

两份图分别满足独立规格：Output[i].toNat等于Input[0..i].toNat之和模2^32，并保持Input和Output有效范围外内容。块数在HLSL内可用((N−1)>>5)+1得到，无需为了首例先加整数除法或多uniform。证明库提供有限和分块、尾块覆盖、唯一写者和模加数学引理，不能复制候选运行函数充当oracle。
